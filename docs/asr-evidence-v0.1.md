# Browser-local ASR source-window evidence journal (integrated; Safari acceptance pending)

## Why this exists

Real classroom C1/C2 window-cache regressions showed two independent failure modes:
- Initial PR #13: C1 828→272 words and C2 717→156 words.
- Second PR #13: C1 828→322 words and C2 717→474 words, despite fixes for punctuation equality and early stable progression.

**Do not merge PR #13**; lexical overlap heuristics, including a hard-coded 64-word draft budget, have not proven safe for real classrooms. PR #12 remains the verified production baseline. The report's original ASR evidence was stored only in private developer test files, so a normal visitor could have permanently lost this evidence even when a mistaken assembly dropped recognized sentences.

This change does **not** pretend to solve word alignment or prevent errors in the live assembled subtitle. It protects **recoverability**: independently save every accepted ASR response before treating its text as a replaceable subtitle hypothesis. No provider keys, original audio, or third-party proxies are included in the evidence file; audio is already saved separately as local WAV chunks.

## Data flow

- `BrowserAsrSession` emits `raw_hypothesis_text` from the actual OpenAI-compatible audio transcription response alongside its `window_start_sample`, `window_end_sample`, `inference_ms`, and `final` metadata. A synthetic flush with no ASR response must not invent a new hypothesis.
- `BrowserAsrSession` **awaits the browser-local evidence-save callback before calling `TranscriptBuffer.update()`**. Even if subtitle projection throws, the raw provider response has already been retained when IndexedDB succeeds. A storage error is reported visibly; the current UI still allows recording, so a recording with a failed journal is **not** a complete evidence set. The user-visible RU subtitle is still generated by the **unchanged main / PR #12** `TranscriptBuffer`.
- IndexedDB `ru-class-local-v1` schema upgrades from version **1 to 2** by adding `hypotheses` keyed on `[lessonId, endSample]`. Existing profiles, lessons and PCM audio are not cleared. The first window at a given sample position is immutable: identical retries do nothing, while conflicting later text for that end sample is reported as a write conflict rather than silently overwriting the original.
- `Settings → Local Data → Download raw ASR windows` (Chinese UI: **设置 → 本地数据 → 下载原始识别窗口**) exports **only that lesson's** original ASR windows. Older lessons from before this update do not have such records. Empty exports are rejected with a clear message.
- User-initiated `Clear local data` deletes the evidence store along with credentials, audio and lessons. API keys are not placed in the JSON download.

## Portable export shape

```json
{
  "format": "ru-class-asr-windows-v1",
  "sample_rate": 16000,
  "windows": [
    {
      "text": "Example recognized utterance",
      "window_start_sample": 0,
      "window_end_sample": 32000,
      "final": false,
      "inference_ms": 730
    }
  ]
}
```

This is directly usable as `{windows:[...]}` input in the existing `scripts/replay-browser-transcript.mjs` regression tool. It is a window transcript **not verified verbatim speech and not word-aligned**. It can be used to compare future algorithms without repeatedly uploading the same classroom audio to an ASR provider. Since each window contains overlapping audio, do **not** concatenate the `text` fields as a final transcript.

## Limits and privacy

- IndexedDB is origin-local and can be wiped or evicted. Explicitly export the JSON and WAV to preserve important classes. A storage failure is shown on the webpage (including after a normal stop), but the JSON may be incomplete; there is no hidden central backup. A page abruptly closed during processing cannot guarantee that the final ASR response was successfully stored.
- A third-party ASR provider receives the user's voice data when the browser makes the user's selected direct request. The RU-Class static host does not receive transcripts, audio or keys.
- The JSON contains **private classroom speech**, sometimes repeated across overlapping windows; never publish it or send it to a public repository.
- This is **not** PR #13 validation, formal v0.1 acceptance, proof of correct live subtitles, 5-minute physical classroom testing or an M4 test.
- A future projection redesign should derive captions from an append-only sample-window evidence timeline and compare it against the same private C1/C2 fixtures. Without word timestamps, preserve ambiguity rather than destructively removing historical speech based on identical words alone.

## Review and physical-browser admission gate (2026-10-17)

Automated test coverage checks the v1 → v2 record-preserving migration,
duplicate-position idempotence, conflicting-response rejection, privacy-safe
export, explicit clear, and connections released on `versionchange`.
A delayed `onsuccess` after a blocked open must be closed; the user receives
a retryable error rather than a silently owned handle.

**These simulated tests are not a Safari or iPad acceptance.**
The code has been forward-ported into main at the owner's explicit
request; the following is the **pending physical-browser acceptance
checklist**, not a pre-merge claim:

1. In real macOS Safari create a **v1** database containing a speech
   profile, an existing lesson and audio samples. Upgrade to this PR;
   verify each original record remains intact. Never commit its token.
2. Open two tabs, trigger a schema upgrade / `versionchange`, confirm
   the old connection is released. If another tab blocks migration, confirm
   a visible error, close the old tab, retry, and verify data persistence.
3. Run real microphone + configured ASR and export one course's JSON.
   Inspect the exported `windows` locally: actual ASR response text and
   integer sample positions must match the private network trace; no
   synthetic `flush`, other course, provider key, or original WAV in JSON.
4. Induce a local evidence-store failure: UI must visibly warn even after
   normal stop, and must not claim that the exported history is complete.
5. Re-run C1 (121 windows), C2 (106 windows), 45 exact-range replays and all
   227 stop-prefix checks with unchanged main subtitle projection.

**Decision:** The previous PR #14 branch diverged from current main, so
its implementation was forward-ported onto a clean main branch and
integrated at the owner's request. **This does not establish a Safari
hardware pass**. Keep Issue #28 open to verify browser-local storage
and export. Treat the journal as a recoverability feature, not
validation of Russian caption accuracy.
