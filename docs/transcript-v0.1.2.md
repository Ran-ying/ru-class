# v0.1.2 · 持续俄语文字缓冲（实现说明与边界）

## 用户看到的变化

从开始一堂课到结束，右侧 RU 实时字幕不再只显示最近 8 秒 Whisper 窗口：服务器累积稳定文字，网页保留其全部内容并叠加一段可改写的临时尾部。在同一个会话中，只有新的稳定文本被追加；从最近音频窗口重新输出的旧词不会被整段追加。停止录音后将剩余尾部归入已确认文字。开始下一堂课时清空缓冲区。

**这里的“稳定”是多个重叠窗口的文字共识，并不等于事实准确或已被 DeepSeek 修正。** v0.1.2 不会提交正式双语历史、消费稳定缓冲、保存文本到磁盘或改变音频录制方式。

## 数据流

- 原有 `AudioWindow` 继续只保留最近 8 秒的音频，Whisper 每次返回这个窗口的原始俄语 `text`。
- 新增主项目 `TranscriptBuffer`：通过俄语词语标准化和重叠窗口的连续词序列对齐构建累积文本。已确认词保持不变，保留最后约 3 个词作为可重写的尾部，防止重复识别结果无限增长。
- 新文本完全缺乏可信锚点时暂时保留原内容并等待另一条相似结果；一次空 Whisper 输出不会擦掉已有字幕，连续空结果或停止录音则会提交剩余尾部。
- 单次 `asr.partial` 内附 `stable_delta`（本次新确认、只可追加）、`partial_text`（覆盖上一版临时尾部）、`revision`（会话内递增序号）；`text` 仍是原始窗口结果，供诊断及旧 Worker 兼容。
- 浏览器把已经收到的 `stable_delta` 拼接保存，仅替换 `partial_text`，据此显示整个课堂的俄语。旧 Worker 若不提供新字段仍降级到单窗口显示，绝不冒充稳定文字。
- 停止时如果音频尚有新样本，最后一次推理会结束并清空临时尾部；如果最后一个音频窗口已经推理完成且没有新增样本，则发出一个只结算文字的 `final: true` 事件。
- 页面仍将文字限制在 RU 区域内部滚动，显示新结果时仅当用户原本处于底部附近才自动滚到最新位置。

## 验收要点

连续 15–30 秒的俄语讲话，等待超过 8 秒后最开始的词仍可见（上滚 RU 框查看）；两次几乎相同的窗口不产生重复段落；老师连续重复“да да да”等单词时，不应因为文本去重把其识别出的重复词全部删掉；Whisper 偶尔返回空文本不闪掉整段；停止后全部文本留在屏幕，开始下一次录音才清空。

## 已知限制

`whisper.cpp` 当前兼容 API **只有整段窗口文字，没有词级时间戳**。相似词串的连续对齐是一种启发式估计，无法数学保证所有重复的口语、剧烈 ASR 改写、极端长静音都零丢词零重复。这些场景应留待有时间对齐、可恢复的原始音频以及更完善的稳定算法来解决。v0.2 将单独实现浏览器录音保存，v0.3 继续处理稳定化与精准时间戳。**目前没有把临时文本落盘，关闭/刷新网页会丢失当次文字，且断网仍会停止采集。**

本次只更新 `ru-class` 的转写处理与界面；`ru-class-asr` 仅同步可选协议字段，不改变它的独立 HTTP 推理服务或 `whisper.cpp`。
