# RU-Class · 浏览器直连 BYOK（v0.6.3）

面向俄语课堂的网页语音转写工具。**无需注册、无需登录、无需向 RU-Class 提交 API Token**。每个访问者自行填写语音、图像、文字 API 地址与模型，个人配置、录音及识别文本只保存在自己的浏览器。网页服务器不提供默认 AI 服务，不接受用户模型配置或音频转发请求。

## v0.6.3 长课加固

- 录音时申请屏幕唤醒锁，电脑放着不动也不会睡眠；切回页面时重新申请。
- 首次录音时申请持久存储，降低浏览器在磁盘紧张时清除课堂录音的风险（是否批准由浏览器决定）。
- 开始录音时检查可用存储，不足 300 MB 时提示（90 分钟录音约需 175 MB）。
- 麦克风被系统暂时静音（切换设备、其他应用短暂占用）不再结束整节课，只提示并等待恢复；麦克风彻底断开仍会停止。
- 识别除每秒定时触发外，也由到达的音频驱动，标签页在后台时定时器被限制也不影响识别。

17 分钟真实课堂录音长测（v0.6.2）：ASR 与文字模型 0 次失败，识别 P90 延迟 0.9–1.9 秒，未随时间增长，页面内存 7–11 MB，历史 283 句，缓冲区中位数 42 字符。

## v0.6.2 稳定性：临时故障不再中断上课录音

此前任何一次语音识别请求失败（网络抖动、请求超时、服务器 5xx、服务器忙 429）都会让整节课的录音停止，并标记为"中断"。现在：
- 临时故障时继续录音（音频照常保存在本地），识别按 1、2、4 秒退避自动重试，恢复后接着出字幕；页面显示"正在重试"，恢复后提示中断期间字幕缺失。
- Token 错误、地址错误等配置问题仍会立即停止；从未成功过的地址连续失败 3 次也会停止，不会悄悄重试。
- 停止录音时服务器正好不可用：最后一段重试几次后放弃，课程仍正常完成。
- 文字模型（DeepSeek）故障：录音中按 5 秒到 60 秒退避一直重试，恢复后补齐历史；此前同一批句子失败 3 次后，本节课剩余时间历史区都不再更新。

浏览器故障注入实测（真实课堂录音）：ASR 502 持续 30 秒、断网 30 秒、DeepSeek 503 持续 70 秒、停止时 ASR 断开，录音均未中断，恢复后 5 秒内继续识别，课程正常完成。

## v0.6.1 修复：录音中历史区不更新

真实课堂录音的识别结果错字较多，文本模型每次都判断为"不确定"而返回 0，句子一直积在缓冲区，直到停止录音才生成历史。现在：
- 提示词明确：错字不是等待的理由，要根据上下文主动修正识别错误（不编造内容）；以 `. ? !` 结尾的片段一般就是句子边界。
- 兜底：最早的待处理片段落后识别进度超过 15 秒时，带 `flush` 标记请求，模型必须至少处理到最后一个句末标点，保证历史区持续前进。

用真实课堂录音 2 分钟实测：修复前录音中历史区始终为 0；修复后边录边生成 41 句，缓冲区通常只有几十个字符。

## v0.6 点击历史句子回放该句录音

历史区里带时间标签（如 `01:23`）的句子可以直接点击，播放这一句在完整录音中的那一段；再次点击停止。录音进行中不能回放，以免外放声音被麦克风录入。不会为每句生成单独音频文件：播放时只从浏览器里已保存的录音块中读取这一句覆盖的范围。

时间来源分两步：
1. **Whisper 分段时间**：ASR 端点支持 `response_format=verbose_json` 时（`ru-class-asr` v0.1.4 起），每个识别窗口额外保存分段起止时间；段内按字符位置估算每个词，进入稳定片段和正式句子。端点不支持时自动退回 `json`，句子没有时间、不可点击，其他功能不受影响。
2. **按录音修剪**：分段可能跨过停顿，估计会偏到静音或相邻句里。播放前读取前后各 1.5 秒录音，按当场噪声底自适应地找出语音段，去掉首尾静音和属于相邻句的语音，补完被截断的词，再前后各留 0.15/0.2 秒。

在 Mac mini M4（whisper.cpp small + Silero VAD）上用合成俄语课堂音频测试 7 轮（含两段未参与调参的留出音频、加噪与混响）：语音覆盖率 98–100%，播放内容约 90–93% 为语音（其余为首尾余量），干净音频的完整句子起止误差多在 0.1 秒内。这是合成语音的结果，不是真实课堂验收；详见 [v0.6 设计与评估](docs/v06-sentence-playback.md)。

## 原始 ASR 窗口保存与导出

新录音会在浏览器自己的 IndexedDB 中，**先保存每次 ASR 返回的原始识别窗口，再执行字幕拼接**。窗口记录包含原始识别文本、16 kHz 采样起止位置、推理耗时和是否为最终窗口；不包含 API Key。可在 **「+」→ 课程管理 → 对应录音 → 下载原始识别窗口** 导出私有 JSON，之后使用离线回归工具复核字幕。旧课堂不会自动出现以前没有保存过的原始窗口。

本次是从 [PR #14](https://github.com/Ran-ying/ru-class/pull/14) 移入当前 main 的功能，不改变原有字幕拼接策略。数据库版本从 v1 升至 v2，原有配置、课堂和音频应保持；自动化回归已覆盖升级与导出，但**真实 Safari/多标签页数据库升级和麦克风导出仍需使用者实测**，详见 [原始窗口保存说明](docs/asr-evidence-v0.1.md) 和 [Issue #28](https://github.com/Ran-ying/ru-class/issues/28)。不要将包含课堂原话的导出 JSON 上传到公开仓库。

## 识别窗口的完整性与配置来源

新录音会在浏览器 IndexedDB v3 中增加独立的证据状态记录；
只有所有原始窗口都已保存、请求计数一致、音频采样范围完整、
且正常停止时才标记为 **完整**。保存失败或被中断会持久标记
**不完整**；早期录音保留 JSON 下载，但完整性显示为
**旧记录：未知**，不会伪造先前未保存的数据。

下载仍使用兼容的 `ru-class-asr-windows-v1` JSON，仅新增
`metadata` 对象：本网页版本、**用户选择**的模型 ID、窗口数、
保存失败计数与证据状态。不存 Token、模型服务网址或课堂声音；
前端也不能从这些字段证明 Mac mini 的实际 `temperatureInc`
或已载入模型版本。真实 Safari 升级/多标签页/异常存储测试
仍由 [Issue #28](https://github.com/Ran-ying/ru-class/issues/28)
验收。

## v0.4 按录音恢复未完成翻译

每次开始/停止录音仍保存独立 WAV、原始识别窗口和
`stableUnits[]`。如果结束录音后尚有稳定俄语没翻译，
或者刷新页面打断了 DeepSeek 请求，可以在
**「+ → 课程管理 → 选择课程 → 对应录音 → 恢复未完成翻译」**
手动继续。程序会读取该录音已持久化的双语句子，
按 *录音 UUID + 稳定单元 ID* 找出尚未处理的前缀，
跳过已经提交的句子，再继续正式断句和中文翻译。
真正重复的同一俄语短语拥有不同单元 ID，不会仅因文字
相同就被忽略。若所有单元已完成，不会再调用付费接口。

**这项操作必须由用户主动点击**，不会在打开页面时
自动消耗模型额度。只对已正常结束并保存了来源单元
的录音开放；中断或没有来源证据的旧录音不得伪造
最终确认的文字。继续处理仍会把这段录音的待处理
俄语发送给用户已配置的文字模型并可能产生费用。

## v0.4 DeepSeek 正式双语历史

**2026-10-18 更新：** 仅发送 Whisper 已确认的稳定俄语，确认后额外等待 4 秒（从 8 秒缩短）；停止录音后后台队列会继续翻译剩余已确认原文，开始下一段录音不会取消旧的已完成录音任务。失败或模型无法断句时不会假装完成，保留原文并提供手动恢复。实际延迟还包含 Whisper 确认及文字 API 的响应时间，不能保证 5 秒内出现中文。

可以在「设置 → 文字」填写自己的 OpenAI 兼容 API 地址、
模型和 Token（例如支持 `/chat/completions` 的 DeepSeek）。
录音时，仅将 LocalAgreement 已确认、且确认窗口结束至少
4 秒的俄语片段提交给所选文字模型。模型执行俄语断句、
有限校正和正式中文翻译；接受结果前必须校验原始稳定
片段前缀，不能凭空消费或删除未处理的原文。

多句结果会依序追加到右上方同一课堂的俄语/中文历史，
底部 RU 只保留尚未处理的文本。原始录音、Whisper 文字和
窗口时间不会被 DeepSeek 改写。新 IndexedDB v5 独立保存
双语句子，刷新后可查看；模型超时不会中断录音。
**文字会发送给用户选择的服务提供商，可能产生 API 费用**；
未配置文字模型时只保留俄语转录。底部实时 ZH 仍是
v0.5 任务。详情：[v0.4 设计与验收](docs/v04-deepseek-bilingual-history.md)。

## v0.3 本地文字来源复核

新的课堂识别窗口 JSON 导出会增加**可选的**稳定文字来源单元
与对应录音 ID（旧记录不生成历史上不存在的证据），保持
`ru-class-asr-windows-v1` 与 `windows[]` 兼容。可以在本机运行：

```sh
node scripts/audit-stable-source.mjs '/你的私人录音-asr-windows.json'
```

程序在本机重放真实 `TranscriptBuffer`，对照稳定文字单元
以及确认窗口的采样位置，只输出数量/异常状态，**不会显示
俄语原文、私有路径或 Token**。完整会话成功重放只能证明
来源记录与字幕程序一致，**不是**证明 Whisper 逐词准确。
不应把私人导出文件上传到公开 GitHub。详见
[来源复核说明](docs/v03-stable-source-watermark.md)。

## v0.3 稳定字幕、来源时间与后续 DeepSeek 输入

RU 实时字幕现在区分**已稳定文字**（深色）与**临时文字**
（浅色、可随下一次识别替换）。每次新增稳定文字会按录音会话
存储为一个来源单元，包含确认它的 Whisper 采样窗口、课程与
录音 ID，以及明确标记为**估计**的确认时间。这里**没有**
Whisper 逐词时间戳，因此不把窗口位置冒充成某句话的准确发声时间。

为 v0.4 DeepSeek 预留的入口只接受 LocalAgreement 已确认的
文字单元，并要求它们在**确认窗口结束之后再经过 8 秒**
才可用于直播处理；录音最终 `flush` 后则可处理剩余稳定
文字。仅仅因为某段音频距离现在已超过 8 秒，不会把尚未稳定
的文字强行确认。**以上是 v0.3 当时的开发边界；现行 v0.4.0 已实现 DeepSeek 正式断句和翻译**。详细见
[v0.3 设计与验收](docs/v03-stable-source-watermark.md)。

## v0.2 课程重命名与跨录音双语历史

左右主区域之间增加一条 **1px 细分割线**。
在左上角「+ → 课程管理」中选中课程，右边点击
**重命名**即可修改课程名称，课程日期维持不变。
重命名会对新的日期/名称做同日重复检查，保留课堂 UUID，
并在同一个 IndexedDB 事务中同步更新该课堂所包含
录音会话的归属元数据。所有 WAV、原始识别窗口、
证据完整性信息和录音 UUID 保持原样；历史旧课首次重命名
也可以获得稳定 UUID。

**一节课堂可录制多段会话**。每段 WAV 和原始 ASR JSON
独立保留，避免停止、暂停或异常时损坏已保存的数据。
「双语历史」按课堂汇总多段会话、依真实开始时间排序，
不同段之间显示时间/分界；俄语显示原识别字幕，中文在
翻译功能上线前明确为“尚未生成”，不伪造翻译。
未来可以生成整节课的连续播放或导出副本，但不得覆盖
原始录音，也不能隐去中途未录制的时间。

## v0.2 课堂选择（课程名称 + 日期）

左上角现为课堂选择器：显示 **日期 · 课程名称**，右侧加号
打开添加课程弹窗，可以输入课程名称与日期（默认今天）。
相同日期的同名课程不可重复创建；日期不同可以同名。

时间轴。已有录音按旧课程名和录制日期归类，不删除或
改写旧记录。新增的 IndexedDB v4 只增加课程目录，不改变
ASR 服务和 SubtitleBuffer。参考
[课堂模型及兼容说明](docs/v02-dated-classroom-identity.md)。

## v0.2 本地课堂录音回放

**「+」→ 课程管理** 中，每堂已保存音频的录音现在都可以直接点击「播放录音」，加载本地完整 WAV 后使用原生播放器暂停、拖动进度或切换课程；原来的「下载 WAV」「下载原始识别窗口」保留。播放器只读取 Safari 当前站点的 IndexedDB，不会向 RU-Class 服务器上传课堂音频。录音时不开放旧课回放；关掉设置或清空数据会释放播放内存。

WAV 重建时检测 PCM 分块缺失和损坏，并对长录音提供容量提醒。**30 分钟合成音频 WAV（约 55 MiB）已纳入自动化验收；MacBook Safari 30 分钟真实麦克风录制、刷新恢复/存储容量仍待用户设备实测。** 原有数据无需迁移，已经保存的旧课堂也可直接播放。使用说明：[v0.2 本地课堂与录音回放](docs/v02-local-recording-playback.md)。

## 运行原理

1. 网页经 HTTPS 加载后，在浏览器的 IndexedDB 中读取自己保存的 API 配置（语音/图像/文字分别独立）。模型设置页一开始同时显示 API 地址和可选 Token，下面是「获取可用模型」按钮；点击后才显示模型下拉框（或在不支持列表时显示手动输入），修改 Token 会使旧模型列表失效。用户可通过「获取可用模型」直接请求自己的提供商 `GET /models`，也可以在该接口不支持时手动填写模型 ID。
2. 用户点击录音，AudioWorklet 在**浏览器**采集音频并重采样成 16 kHz 单声道；最新 **8 秒 PCM 音频**保存在浏览器内存中。约每秒向用户自己配置的兼容 ASR API 发起一次 `POST /audio/transcriptions`，请求串行、429 限次重试。
3. 浏览器本地运行文字对齐和稳定化算法，展示 append-only 已确认俄语与可改写尾部。正常停止会最后一次推理并结算尾部。
4. 浏览器把课堂文本和录音分块写入 IndexedDB。停止后在「+」→ 课程管理查看课堂录音并下载 WAV。录音数据不传给 RU-Class 网站服务器，但**会按用户选择的服务商协议发送片段给语音 API**。
5. 浏览器已支持文字模型 `/chat/completions`，仅消费满足 +4 秒确认边界的俄语，将正式 RU/ZH 句子保存到 IndexedDB v5；可在课程管理中主动恢复已完成录音剩余翻译。图像模型仍仅支持配置。**下方实时中文字幕尚未实现**，属于 v0.5。

### 核心边界：不提供 CORS 代理

浏览器直接请求自己的 API，要求提供商支持 CORS（跨域），包括携带 `Authorization` 时的 `OPTIONS` 预检。**RU-Class 不为不支持 CORS 的 API 提供中转或绕过方式**。遇到 CORS 错误请换用支持跨域的 API，或在自己控制的 API 服务中开启严格 Origin 白名单。网络连通性和服务端是否支持 CORS 是不同概念，浏览器可能将两者都报告为 `Failed to fetch`。

自行部署的 [ru-class-asr](https://github.com/Ran-ying/ru-class-asr) 已提供可配置 CORS：配置 `cors.allowedOrigins` 为网页实际 HTTPS Origin，ASR 运行时仍独立保管其 API Key。ASR 在用户自己的机器上时，API 必须具有浏览器可访问的 HTTPS 入口，浏览器的 `localhost` 不是远程服务器的 localhost。

## 浏览器本地数据与隐私

- API 地址/模型/Token：IndexedDB `profiles`，本地存储；不提交给 RU-Class 服务器。
- 课堂文本/课程名/时间：IndexedDB `lessons`。
- 录音音频：IndexedDB `audio`，16kHz PCM16 分块；下载时在浏览器封装成 WAV，录音时不需要积攒整段音频到 RAM。
- 点击「清空此浏览器的全部数据」会删除该站点的模型配置、课堂文本及录音。清除浏览器网站数据同样会丢失这些信息；不同设备之间不会自动同步。
- API Token 可被同源网页 JavaScript 读取，因此应该避免使用权限过大的长期密钥；网站启用限制性 CSP，不加载第三方脚本，生产环境必须使用可信 HTTPS 域名。**浏览器存储不等于加密保管密钥**。
- 录音保存受浏览器存储空间配额、无痕浏览及系统回收策略限制；重要课堂请自行下载 WAV 保留备份。当前不支持断网离线 ASR。

## 本地运行

Node.js 22.6+：

```sh
npm ci
cp config.example.json config.json
npm run dev
# 浏览器打开 http://127.0.0.1:3000
```

`config.json` 仅包含可选的 `listen.host`、`listen.port`、`site.publicOrigin`，没有模型地址或共享站点访问令牌。没有配置语音 API 时依然可以打开网页，在设置中填写自己的 API 后录音。用户模型配置不再存放到服务器的 `data/local-models.json`，旧文件可以在核对迁移后自行清理。

部署到公网时也只需要提供**静态文件**（`apps/web/`，需将所有 JS 模块和 `capture-worklet.js` 原样托管）与 HTTPS，甚至不需要 Node.js 常驻。仓库自带的 `npm run dev` / `npm start` 只是提供静态页面的轻量 HTTP 服务，不含 API 路由或 WebSocket 录音网关。

### 旧架构说明

v0.1.x 的 Node.js 音频 WebSocket 网关、`config.json` 里的全局模型和公网站点 Token 已不再用于**正式启动入口**；相应历史代码/测试保留在仓库供迁移比对。不要沿用旧的 Nginx 到 `/ws/client` 转发说明。参见 [浏览器直连架构](docs/browser-direct-byok.md)。


### 文字 API 低延迟设置与本地统计（2026-10-18）

当「文字」API 地址属于官方 `api.deepseek.com` 时，RU-Class
为正式句子翻译发送 `thinking: {type: "disabled"}`、
`max_tokens: 2048`、`stream: false`，防止默认深度思考造成
不必要的输出 Token 和延迟。其他兼容 API 保持原有参数。
如果 DeepSeek 的回复因长度限制截断，系统拒绝保存不完整译文，
保留原始俄语等待有限重试或用户手动恢复。

在「设置 → 关于」可查看此浏览器保存的文字模型每次请求耗时、
Token 用量和错误状态。只有 API 明确上报的 Token 才显示数字，
未提供推理 Token 时显示「—」而非 0。诊断信息不含密钥、
课堂原文和翻译正文；清除本地数据时同时删除诊断信息。
实际效果须在 MacBook Safari 和真实模型上继续验收。


### API 配置：自定义 JSON 参数（2026-10-18）

设置 → API 配置 → 各模型卡片 →「额外请求参数（JSON）」可以展开文本框。
文字 API 把自定义 JSON 并入 `/chat/completions` 请求体；官方 DeepSeek
自动填入关闭思考模式、2048 Token 和非流式的默认值，支持编辑。
语音 API 使用 multipart 表单，只接受 JSON 对象中的标量额外字段；
图片模块暂只保存参数。模型、输入消息、音频文件、语音识别语言
和响应格式不能被额外参数覆盖。额外参数仅在本地浏览器保存，
模型列表的「测试连接」不保证推理接口支持所有自定义参数。


### 课程列表及历史区滚动（2026-10-18）

课程管理左侧列表按创建／添加时间倒序排列，最新添加的课程在最上方，
不以课程的上课日期代替创建时间。旧版本隐式生成的课程按最早可恢复
录音创建时间排序。右侧正式俄中历史不保留外层左右留白，句子依然
由横向边框和中间竖线分隔。如果阅读者已经滚动到最下方，新译文追加
后自动跟随到底部；如果阅读者向上滚动，则保持当前阅读位置。
切换到另一课程时默认展示该课程最新的句子。重新加载历史使用
完整 DOM 交换，避免异步清空造成滚动位置丢失。


### 优先处理完整句子（2026-10-18）

在一段录音进行中，Whisper 已确认的俄语一旦出现完整句子，
立即按原文顺序发送最多两句给文字模型，不再额外等待 4 秒。
单次稳定增量即使包含多个句子，也拆分为独立、带记录 ID 的
不可变来源单元（不代表语音逐词时间戳）；未识别完成的临时文本
不能提前发送。无法明确断句的稳定文字仍保留之前的 4 秒保守
等待路径。每次返回须先保存正式俄中句子再移除下方相应原文，
停止录音后继续处理剩余已确认文字。实际延迟仍受语音识别
确认、网络与文字模型响应影响。
 
### 无标点俄语的及时语义判断（2026-10-18）

Whisper 的 `stable_delta` 已经确认、但没有句号的俄语，也可能实际上表达
了一句完整的话。现在 RU-Class 会在至少两次独立确认窗口、且累积足够
稳定上下文后，允许**现有 DeepSeek 翻译请求**判断这句话语义上是否已经结束；
单个长稳定片段也必须达到更高的词数门槛。只有模型返回合法的
`consumed_units` 及准确的完整来源前缀，且双语句子先写入 IndexedDB，
原文才会从下方移到上方。语义仍不确定时允许返回 0，直到有新增确认
文本再扩大上下文，避免反复向 API 发送同一段无标点片段造成费用。
已有标点的完整句子仍走最快的即时通道；短小无标点片段仍采用此前
确认后 4 秒兜底。没有精确音频停顿或逐词时间戳时，不将停顿推测视为
确定的句子完成证据。判断结果仍受 ASR 质量及模型推断准确度影响。


## v0.5 候选：Mac mini M2M100 实时中文字幕

Mac mini M4 已在用户设备上完成 M2M100 INT8 和 Whisper Small 同时加载，
本地短句翻译 293 ms，受认证 Node API 路由转发约 357 ms（仅两个短句
样本；还没有连续 Safari 课堂延迟或语义质量验收）。
在「设置 → API 配置 → 语音」中启用「本地实时中文」后，
公开 RU-Class 页面**仅对当前用户配置的语音 API** 追加
`/translate` 路由发送当前下方尚未进入历史的俄语。
既没有默认 ASR/翻译服务器，也没有中央转发代理。
例如语音 API 地址 `https://ai.example.test/v1` 会调用
`https://ai.example.test/v1/translate`，复用相同 Bearer Token。
如果自带语音服务未部署 `/v1/translate` 或没有为网页来源开放 CORS，
会提示本地翻译不可用，但 Whisper / DeepSeek 正式历史不受影响。

下方中文使用单独 `LiveTranslationWorker`，700ms 合并、至少
1.5s 请求间隔、串行最新版本任务、10s 超时；只接受当前
`recordingId + revision` 对应的结果，不把临时结果保存为正式句子。
下方 RU 始终来自不可变稳定原文剩余部分和可修订 ASR draft。
v0.5.1 起下方中文不再以灰色半透明显示：只有对应当前俄语快照的
翻译片段才会以深色正常显示。实时翻译输入是**下方全部尚未写入正式历史
的稳定俄语 + 当前可修订的 ASR 草稿**（草稿通常来自滚动 8 秒音频窗口）。
超出单次本地模型输入限制时，系统按原顺序拆成最多 380 字符左右的小段，
逐段翻译并拼接，按片段复用未改变的翻译，不再丢掉前面的稳定原文。
尚未处理完时提示已完成的段数，避免把部分译文误称为全部完成。
正式 DeepSeek 历史与下方临时中文继续隔离。录音停止／故障立即清理；
开关仅留在当前浏览器，不增加新的密钥。

### v0.5.1 句子进入正式历史的延迟修复（2026-10-20）

在相邻、**不同采样时间**的 Whisper 8 秒滚动窗口对同一段俄语达成
明确的一致性时，可提前确认句号、问号、感叹号结尾的完整句，
不再机械保留其最后 3 个词。对于连续两个完全相同的无标点假设，
也可确认除末尾 3 个词外的共同前缀，再由 DeepSeek 评估语义是否
已构成完整句子。相同采样窗口重放和空窗之后的重复假设**不算**
新的确认。只有稳定来源经过正式翻译和 IndexedDB 成功保存，
才会被从下方清除，同时**立即绘制**到上方 RU/ZH 历史，
而非等待整门课程重新读取。DeepSeek 仍可判断不完整并返回不消费，
因此不能保证每句话固定多少秒内被确认，尤其不能把尚未确认的
Whisper 草稿冒充正式记录。
